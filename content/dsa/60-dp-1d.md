## Why this matters

DP is where many candidates stall. Master state definition on 1D problems before grids/knapsacks.

## Definitions

- **Dynamic programming (DP):** Solving a problem by combining overlapping subproblems with optimal substructure, storing answers to avoid recomputation.
- **State (`dp[i]`):** A precisely defined meaning for “the answer for the first i items / ending at i / using amount i.”
- **Transition:** The recurrence that computes a state from previously computed smaller states.
- **Base case:** The simplest states with known answers that seed the recurrence (e.g., `dp[0] = 0`).
- **Overlapping subproblems:** Subproblems that recur many times in naive recursion — the reason memoization/tabulation helps.
- **Optimal substructure:** The property that an optimal solution is built from optimal solutions of smaller subproblems.
- **1D DP:** DP indexed primarily by one dimension (index, amount, or length), often space-optimizable to a few variables.

## Playbook

1. Define `dp[i]` in words  
2. Transition  
3. Base case  
4. Iteration order  
5. Answer location

## Climbing stairs / Fibonacci

```java
int climbStairs(int n) {
  if (n <= 2) return n;
  int a = 1, b = 2;
  for (int i = 3; i <= n; i++) { int c = a + b; a = b; b = c; }
  return b;
}
```

## House robber

```java
int rob(int[] a) {
  int prev2 = 0, prev1 = 0;
  for (int x : a) {
    int cur = Math.max(prev1, prev2 + x);
    prev2 = prev1; prev1 = cur;
  }
  return prev1;
}
```

```csharp
int Rob(int[] a) {

    prev2 = prev1; prev1 = cur;
  }
  return prev1;
}
```

## Coin change (min coins)

```java
int coinChange(int[] coins, int amount) {
  int[] dp = new int[amount + 1];
  Arrays.fill(dp, amount + 1);
  dp[0] = 0;
  for (int x = 1; x <= amount; x++)
    for (int c : coins)
      if (c <= x) dp[x] = Math.min(dp[x], dp[x - c] + 1);
  return dp[amount] > amount ? -1 : dp[amount];
}
```

```csharp
int CoinChange(int[] coins, int amount) {
  var dp = Enumerable.Repeat(amount + 1, amount + 1).ToArray();
  dp[0] = 0;
  for (int x = 1; x <= amount; x++)
    foreach (int c in coins)
      if (c <= x) dp[x] = Math.Min(dp[x], dp[x - c] + 1);
  return dp[amount] > amount ? -1 : dp[amount];
}
```

## LIS — O(n log n) patience

Maintain tails of piles; binary search lower bound.

```java
int lengthOfLIS(int[] nums) {
  int[] tails = new int[nums.length];
  int len = 0;
  for (int x : nums) {
    int i = Arrays.binarySearch(tails, 0, len, x);
    if (i < 0) i = -(i + 1);
    tails[i] = x;
    if (i == len) len++;
  }
  return len;
}
```

## Interview Q&A

- **Q:** Top-down vs bottom-up?
  **A:** Memo recursion to discover; bottom-up for speed/clarity once known.
- **Q:** How to spot DP?
  **A:** Optimal substructure + overlapping subproblems; “min/max/count ways”.

## Pitfalls

- Wrong loop order for unbounded vs 0/1  
- Using `int` overflow on “number of ways”

## 60-second answer

“I define dp[i] as the answer for prefix i, write transitions from smaller prefixes, and space-optimize when only a few prior states matter. Coin change and robber are my 1D templates.”
